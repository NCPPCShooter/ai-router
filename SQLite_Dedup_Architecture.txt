OVERVIEW
--------
Rather than emailing Cindy a full digest of job search results each morning,
the router now stores all parsed job postings in a local SQLite database and
sends her a short notification email summarizing how many net-new postings
were found that day.

The database is the source of truth. The email is just a daily signal.


ARCHITECTURE
------------

  Windows Task Scheduler (6 AM daily)
        |
        v
  scheduled_search.py
        |
        |-- loads prompt files from Job-Search-Prompts repo
        |
        |-- calls search_with_grok(prompt)  [router.py]
        |       |
        |       v
        |   Grok (xAI native SDK, live web search)
        |   returns raw free-form text of job listings

DATABASE SCHEMA
---------------

  Table: job_postings

  Column        Type     Notes
  ----------    -------  -----------------------------------------------
  id            INTEGER  Primary key, auto-increment
  fingerprint   TEXT     SHA-256 of (title + company + url), UNIQUE
  title         TEXT     Job title
  company       TEXT     Company name
  url           TEXT     Job posting URL (if available)
  location      TEXT     Location / Remote
  salary        TEXT     Salary range (if listed)
  source        TEXT     'US Search' or 'Global Search'
  raw_snippet   TEXT     Raw text block from Grok (capped at 2000 chars)
  date_found    TEXT     ISO date: YYYY-MM-DD
  created_at    TEXT     ISO datetime of insert


DEDUPLICATION LOGIC
-------------------

  Fingerprint = SHA-256( lower(title) + "|" + lower(company) + "|" + lower(url) )

  - If fingerprint already exists in DB → skip (duplicate)
  - If fingerprint is new → insert record
  - A job reposted at a new URL is treated as a new posting (correct behavior)
  - Comparison is case-insensitive and whitespace-normalized


EMAIL BEHAVIOR (NEW)
--------------------

  OLD: Full digest email with all job results formatted by Claude
  NEW: Short notification email only

  Email contains:
    - Count of new postings added today
    - Count of duplicates skipped
    - Running total in the database
    - Bulleted list of net-new postings (title, company, location, salary, url)
    - If zero new: plain statement that all results were already seen

  Subject line example:
    "Job Search Update — 7 New Postings — June 15, 2026"
    "Job Search Update — 0 New Postings — June 15, 2026"


QUERY HELPERS (job_db.py)
--------------------------

  init_db()                     Create DB and table if not exists
  store_jobs(raw, source)       Parse + dedup + insert; returns summary dict
  get_all_jobs(limit=100)       Most recent postings
  get_jobs_by_date(date)        Postings found on a specific date
  get_total_count()             Total unique postings in DB
  get_db_path()                 Returns resolved path to .db file

  CLI quick-check:
    python job_db.py
    → prints DB path, total count, today's postings
